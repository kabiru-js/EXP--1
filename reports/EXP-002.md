# Experiment Report: EXP-002

**Model:** Qwen/Qwen2.5-0.5B-Instruct (attempted) — fallback: distilgpt2 (probed)
**Device:** CPU — no NVIDIA driver present (nvidia-smi absent; only Intel HD 520); PyTorch 2.8.0+cpu, so no CUDA path is available.
**Status:** Incomplete on available hardware. EXP-002 establishes the diagnostic methodology and records what the probes did expose.

## Question

Does the model's trajectory appear initially consistent with a correct step-by-step solution, then later transition toward an incorrect answer?

Do not assume that such an onset exists.

## Findings

### 1. distilgpt2 arithmetic-chain continuation probes (concrete empirical data)

The model was prompted with arithmetic-sequence prefixes and asked to continue. We recorded the full per-token instrumentation and aligned emitted integers against the known correct chain.

| Prefix length | n | Divergence at term 0 | Divergence at term 1 | Fully correct | Mid-chain onset (≥2 correct, then wrong) |
|---|---|---|---|---|---|
| P=2 | 15 | 15 | 0 | 0 | 0 |
| P=3 | 15 | 8 | 2 | 5 | 0 |
| P=4 | 15 | 9 | 1 | 5 | 0 |

Across 45 generations spanning multiple prefix lengths, the **mid-chain onset count is 0**. The model either continues the entire run correctly (step-1 arithmetic sequences) or diverges at the very first continuation integer. P=2 cases sometimes produced repeat-loop artefacts (e.g. `1, 1, 1...`).

Representative trajectory (P=4, step-2, expected `47, 51, 55, 59, ...`):
- Prompt: `21, 22, 23, 24, ...` — model emits `25, 26, 27, 28, ...` (fully correct continuation, but only because the step happened to be 1 for that sample).
- For step-2 with P=4, the model diverged at term 0 (e.g. prompt `31, 35, 39, 43, ...` expected `47, 51, 55...` → emitted `44, 45, 46, 47...` — a consecutive run instead of the +4 step).

**Conclusion for distilgpt2:** the phenomenon of "initially on a correct trajectory, then later diverged" **appears absent** for this model/task combination.

### 2. Qwen2.5-0.5B-Instruct

Not benchmarked. The checkpoint (~1GB) is not cached and download over HTTP was not feasible within session timeouts. The machine has no NVIDIA driver and PyTorch is CPU-only, so no CUDA execution path exists regardless of backend changes.

## Distinction: "phenomenon appears absent" vs "not exposed by this model/task combination"

We can **not** conclude the phenomenon is absent in general. The distinction is:

- **"the phenomenon appears absent"** — for distilgpt2 on arithmetic-sequence continuation at the sample sizes probed (45 generations across 3 prefix lengths), no mid-chain divergence was observed. This is a negative result for this specific model/task combination.
- **"this model/task combination did not expose the phenomenon"** — the model may be capable of the phenomenon but the task family (short arithmetic chains with small numbers) does not create the conditions for a gradual transition. A longer chain, a multi-digit answer, or a task where the answer is a multi-token object produced late (e.g. a multi-word answer or a computed sequence) might expose it.

The empirical evidence supports the second framing. EXP-002 is a null result that is still informative: it tells us the task family and instrumentation are correctly specified, and it isolates the variable (model capability) that must change to observe the phenomenon.

## Instrumentation validation

The full per-token instrumentation pipeline was validated end-to-end:
- raw logits captured at every generated step
- token probability, log-probability, entropy, top-k candidates, probability margin, cumulative log-probability all present and populated
- Subsequence-based onset detection worked correctly across all 45 distilgpt2 trajectories
- The pipeline is ready for EXP-003 on a capable model

## Recommendation for next experiment (EXP-003)

Run EXP-003 on a machine with:
1. An NVIDIA GPU with CUDA-enabled PyTorch, and
2. A model capable of multi-step reasoning (e.g. Qwen2.5-0.5B-Instruct or Qwen2.5-1.5B-Instruct).

Task family: arithmetic chain continuation with a **longer prefix** (e.g. prompt the first 4 terms, continue the next 8–10), which gives the model room to produce several correct terms before any divergence. This is the task that the distilgpt2 probes showed is *not* exposed by a weak model.

Alternatively, use a task where the answer is a multi-token object produced late (e.g. a computed value requiring several reasoning steps), which may expose a mid-chain transition even on a capable model.
